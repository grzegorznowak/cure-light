+### 0.3a Mechanical changed-range census
+
+After the `claims_prepare`/`claims_finalize` run and before any split or the Phase-0 gate, the coordinator produces the **changed-range census** with the engine's installed `cure_light_census` plugin:
+
+```text
+census_run   {repo: <subject_path>, base_ref: <base_oid>, subject_ref: <subject_oid>, run_dir: <run_dir>}
+             # local; remote: {review_target, run_dir}; run_dir outside the subject repo, fresh
+             → census.json (changed-range-census/1: census_hash, recipe_hash, parents, events, partition) + census-check.json
+census_check {repo: <subject_path>, census_path: <run_dir>/census.json}
+             # independent offline recompute; permission = null
+```
+
+Census and claim runs use **separate, fresh roots**; a reused/non-fresh root is refused, and the run dir must not be inside the subject repo. **A census grants nothing and is not fed into the claim run.** Two-dot `base..subject` semantics only (never a merge-base substitution); `--stat` is orientation only, never the denominator. Parent units are the `git diff -U0` edit blocks; deletions, renames, mode/binary/submodule changes and other no-text edits are explicit metadata events with old/new path/blob or OID evidence. The artifact records parents/events counts, unique changed lines by side, the recipe + git version, `recipe_hash` and the canonical `census_hash`; `census_check` independently recomputes it under the pinned recipe. A `partition.ok:false` result (with `partition.errors`) is a partition/extraction failure; `BAD_INPUT`/`UNSUPPORTED_RUNTIME` cover usage/environment errors (git missing, bad refs, run dir inside the repo). No agent ingests the whole diff; contract-token ↔ path/symbol overlap may optionally yield candidate claim links (cheap, discovery-only); a missing candidate link never removes a unit from the denominator. Never hand-edit a census artifact, and never reuse one across review states — a re-pull has new OIDs and recomputes. Note: `cure_light_census` gates **claim-registry** completeness only (`complete_registry_claims`, `finalized_unclaimed`); changed-unit coverage is `census.partition.ok`. The plugin provides **no join** between the two — the coordinator joins census parents/events with registry claims/units to build the state's coverage ledger (notebook-plan-contract.md, Coverage pages).
